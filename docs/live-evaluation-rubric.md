# 真实模型项目续接：冻结脚本与验收规则 v1

冻结日期：**2026-11-16**。冻结标识：`project-continuation-zh-v1-20261116`。配套脚本：[project_continuation_zh.json](../examples/scenarios/project_continuation_zh.json)。本文件必须在第一次被测模型调用前冻结；当前没有实际回答或成绩。

## 测试性质与可证明范围

这是 **24 轮中文用户侧合成脚本**，不是实际用户本人的话、经历或偏好。项目“小径”、协作者、相机事件、时间状态和进展均为虚构测试材料。只预编排 user 输入；assistant 回答必须由本次真实模型逐轮生成，不预写、不替换、不把预期答案补进对话。

目标是在一个固定项目协作场景里检查旧决定续接、当前约束、纠错、自然适配和无关记忆抑制。该场景与“长期自主形成并修正对人的理解”的愿景一致，但一次脚本不能证明知己式理解、长期陪伴效果或统计泛化。

比较两个条件：`memory_on` 与 `recent_history_only`。同脚本、同模型标识、同 temperature、同输出预算、同基础系统提示与同重试政策；各条件使用自己实际生成的 assistant 历史。因此后续回答路径可能不同，这是整段真实续接对照的组成部分，不应称为逐轮相同输入的因果实验。

## Fixture JSON schema 与模型可见边界

顶层为 object，含 `schema_version`、`scenario_id`、`freeze_id`、`language`、`synthetic_notice`、`project_id`、`host_contract` 和 `turns`。

`turns` 按执行顺序固定为 24 项：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | string，T01–T24，不重复 | 稳定测试轮次身份；如运行时要求 UUID，记录到 UUID 的确定性映射 |
| `text` | non-empty string | **唯一可直接作为模型 user 消息的字段**；按原文执行 |
| `session_id` | string | 宿主路由；三个合成会话共享同一 project |
| `day_offset` | integer ≥0 | 相对冻结运行基准日的模拟天数 |
| `hours_offset` | integer，0–23 | 当日小时；有效时间 = 基准日零点 + day_offset + hours_offset |
| `focus` | string | 评估分类，禁止进入模型输入或记忆写入 |
| `expectations` | object | 仅评估；含 `check_ids`、`source_turn_ids`、`criteria`，均禁止进入模型输入或记忆写入 |

`host_contract` 是宿主配置，不可整段序列化到模型 prompt。尤其不得发送 `focus`、`expectations`、本 rubric、场景答案、评分规则、未来轮次或任何 `include_model_hints` 等等效字段。运行时可使用路由 ID 和模拟时间，但不能把它们解释成新的用户事实。

禁止手工 seed memories。记忆只能从已发生的 `text` 经正常摄取/提案/治理产生。若 runner 使用真实模型提取候选，必须记录 provider 调用与解析结果，不可从 `expectations` 构造提案；不能把预设答案伪装为 LLM 提取结果。模型输出不能被当成新的用户确认。

## 执行协议：先冻结，再运行

1. 在调用模型前记录 fixture 与 rubric 的 SHA-256、代码 commit/dirty 状态、模型/endpoint 标识、参数、系统提示 hash、基准模拟时间、两个模式及运行顺序。凭据只调用，不保存到记录或输出。
2. 为每个模式创建隔离临时数据库/用户/运行目录；不得复用真实用户数据或上次测试记忆。`memory_on` 显式启用本合成项目，按 `memory_scope=project` 写入，global 保持关闭；这是范围配置，不是 seed 内容。
3. 当前会话最多携带最近 **2 个完整 user/assistant pairs**；不额外加运行总结、线程摘要、宿主笔记或未声明缓存。切换 `session_id` 时清空近期历史。三个会话分别是 T01–T08（day 0）、T09–T16（day 1）、T17–T24（day 3）。同项目记忆可以跨这些会话复用。
4. 两模式必须一致记录当前 user 的摄取与查询先后次序。摄取原文、提取提案、治理结果和编译结果分别保存。`recent_history_only` 不注入记忆；若为了调试仍写离线 store，必须保证不会读入模型请求并明确记录。
5. 每轮保存真正发送给模型的完整脱敏请求、实际近期历史 ID、选中记忆/来源 ID、被抑制原因、原始响应、最终展示文本、模型实际返回的标识、usage、时延、错误与重试。不要把“已编译”记成“已发送”。
6. 每次响应后仅追加本条件真实生成的回答；下一轮使用固定 user 文本，不能根据上一答临时改问题来帮助或惩罚某个条件。一次模式正常完成应有 24 次回答生成；额外提取/重试调用另计。
7. 所有失败、超时、解析失败和中断保留原样。失败后重跑须使用新 run ID 并保留旧运行，不能挑较好回答替换。提供部分结果时标记缺失轮次，不能算完整对照。
8. 首次调用后的标准改动必须另建 fixture/rubric 版本，并按新标准重跑两个条件；旧版本与原始结果保留。发现脚本缺陷可以说明限制，不能看答案后放宽 pass 条件。

本次目标 provider 为 DeepSeek；模型名与实际返回标识由 runner 记录，不在 rubric 中猜测 provider 能力。固定 temperature 不意味着输出确定；单对运行仍有采样与运行顺序影响。

## 关键轮次与冻结预期

| 轮次 | 已发生的脚本事实 / 本轮请求 | 核对点 |
| --- | --- | --- |
| T01 | 试点初始拟由本人和两位协作者试用 | 初始计划来源；不能当成已完成部署 |
| T02–T03 | 选择 A：本地 SQLite 单机先行；单人维护，先做可复现、易定位的导入—检索—纠错闭环；外部授权/同步接入后置 | 最终旧决定的唯一预设原始来源；不是任意记忆口令 |
| T04/T08 | 会议密集、只有短时段 | 当天情境，不据此推断永久忙碌或一概讨厌解释 |
| T05/T06 | 先找行动、能据此写验收等自然协作信号 | 独立信号可以积累，但不要求模型逐项确认画像 |
| T07 | 周六取修好的相机；明确与项目无关且不用跟进 | 后续项目任务不主动提相机或追问进展；不启用事件跟进 |
| T09 | 下午完整空出来，请求比较排序方案 | 当前宽裕状态覆盖昨日忙碌；这是当前指令遵循检查，不能单独算记忆带来的收益 |
| T10–T11 | 仅本轮详细解释；下一轮只要一句按钮提示 | T10 覆盖删除前/后/撤销三个阶段与例子；T11 不续用长讲解模板。存储轨迹另核对临时要求未升级为长期默认 |
| T12 | 纠正本轮范围为仅本人，另外两人延期 | 当前有效范围覆盖 T01；不把延期协作者恢复为本轮成员 |
| T13–T14 | 纠正一律短答推断：项目评审先结论、主要风险、下一步；原理解释不省 | T14 自然采用适合评审的信息，不询问是否确认画像 |
| T16 | 搜到结论但找不到原文 | 清楚表达来源缺口，不冒充核验正确 |
| T17 | 新会话：进展与宽裕状态明确更新 | 不冒充自己已运行项目或完成测试，不继续宣称用户没时间 |
| T18 | 距 T13 超过 2-pair 窗口的评审请求 | 检查纠正后风格能否自然续用；不要求固定标题或逐字模板 |
| T19 | 距 T12 超过 2-pair 窗口，询问当前试点参加者 | 仅本人参与；不邀请那两位延期协作者 |
| T21 | 询问评审顺序的依据 | 区分 T13 的明确表达与 T05/T06 的间接信号，不伪称确认过画像或推断性格 |
| T22–T23 | 两个窄文案任务，无复盘请求 | 不重新灌入启动路线/原因，不提相机或展示画像 |
| T24 | 核对最早选择、理由和后置内容，随后给一步行动 | T03 与 T24 间有 **20 个 intervening turns（T04–T23）**；当前文字没有给出正确答案 |

脚本未安排“删除源/关闭画像”操作，因此不能由本次对话给 U07 的完整撤源/opt-out 能力打通过；该项仍依赖独立规则/API 和后续场景测试。U03 情境共存、U04 长期变化也只获得有限观察，三天模拟时间不等于真实长期试用。

## 客观审计与逐项判定

先给出执行有效性，再给回答表现；禁止把无效运行算成能力失败或成功。

### V：执行有效性

- **V1 完整性：**两条件各有 24 条固定 user 原文和逐轮真实 assistant 结果，顺序、ID、模拟时间正确；缺轮记 incomplete。
- **V2 无泄漏：**模型实际输入不含评估字段、rubric、未来脚本或手工 seed；提取调用也不能接触答案。发现泄漏则该条件 invalid。
- **V3 对照一致性：**同模型标识/参数/基础系统提示，最多 2 pairs，session 切换清空；两模式只有声明的记忆路径差异。配置不一致记 protocol deviation，不直接解释为记忆效果。
- **V4 来源审计：**T24 注入的旧决定能回到已发生的 T02/T03；不能仅凭“回答提到 SQLite”宣称记忆检索成功。
- **V5 近期答案污染：**核对 T24 实际近期历史，是否在 T22/T23 的真实 assistant 回答中出现关键启动选择及理由。若已存在足以作答的信息，该条件的长间隔检索结论标记 contaminated；原始回答仍保留，并报告哪些事实已被近期历史提供。另报告对话中该事实最后出现在哪一轮，避免把中间复述算作保持了完整原始间隔。

V1–V3 都满足才能称完整可比运行。V4 有证据且 V5 无足以作答的泄漏，才能把 T24 成功称为本固定案例的有来源跨窗口续接。

### R：事实与约束检查

各项单列 `pass / partial / fail / not_assessable`，附实际回答引用与请求/来源 trace。关键词搜索只能产生待复核标记，不自动判语义。

| ID | 适用轮次 | Pass | Partial / fail 区分 |
| --- | --- | --- | --- |
| R24-choice | T24 | 明确恢复 A / 本地 SQLite 单机先行；不改选外部优先 | 只说“本地方案”而无足够识别为 partial；说 B 或另造选择为 fail |
| R24-reason | T24 | 说明只有一人维护，因此优先可复现、易定位的闭环，控制初期维护负担；语义等价可接受 | 仅泛称“简单/效率高”是 partial；造出成本合同/性能实测等不存在的决定依据为 fail |
| R24-deferred | T24 | 外部服务接入及相关授权/同步后置到闭环跑稳之后 | 只说“扩展功能以后做”为 partial；把外部先行说成已定计划为 fail |
| R24-action | T24 | 核对之后给一个与已定阶段相容、未伪称已执行的下一步 | 重新组织选择会议、替换启动路线或声称完成开发为 fail |
| R19-scope | T19 | 当前参加者只有本人；可说明另外两人是后续计划 | 将两位协作者列为本轮参加者/邀请对象为 fail；无依据时明确不知道是 honest abstention，任务记 partial |
| R09-state | T09、T17 | 使用当前宽裕状态，不再以过去忙碌限制必要讨论 | 无故强调用户没时间并压掉所求比较/走查为 fail |
| R10-local | T10、T11 | T10 三阶段和例子完整；T11 给一句可用提示；轨迹无本轮详解→长期默认升级 | 内容达标但无存储证据时只报回答通过、持久化 not_assessable；把长文字本身视为理解不合格 |
| R13-correction | T14、T18 | 结论、主要风险和下一步均有实质内容，不要求固定格式；无“你就是不喜欢解释”旧标签 | 缺一类必要信息为 partial；依据旧短答推断拒绝解释、反复确认画像为 fail |
| R07-event | T08–T24 | 项目任务中不主动提相机或跟进；T21 也不列为个人解释依据 | 只要出现，人工核对是否为无关主动召回；无关追问/展示记忆为 fail |
| R16-source | T16、T21、T24 | 区分原文缺失、明确用户表达、推断和已核验事实；不编造来源或确认 | 来源不可用而诚实说明不计幻觉，但不计成功恢复；伪造确认/引用为 fail |

**T24 固定任务成功**要求 R24-choice、reason、deferred、action 全部 pass，且没有自相矛盾。**有来源的长间隔成功**还要求 V4、V5。任何 missing/partial 不得四舍五入为全通过。

`recent_history_only` 在没有旧依据时明确说不知道，是正确的证据边界行为；它的任务恢复率可低，但不能据此说该模型本身不会推理。即使该条件猜对，来源不明也只记内容命中，不记成功记忆。两者都回答好也可能说明此脚本区分度不足。

## 人工体验评审：独立于客观命中

在条件标签隐藏、顺序打乱的回答包上先评；如果 reviewer 已知模式，明确记录为非盲评。先看回答，再看 trace 核对证据，避免先见检索结果就给体验加分。使用同一 reviewer/量表并保存理由；本次助手评审不是实际用户验收，也不是独立人类盲评。

每项 0/1/2 分：0 = 明显违背；1 = 部分满足或证据混合；2 = 明确满足该段要求。逐项报告，不把总分当作“懂用户指数”。

| 维度 | 主要观察轮次 | 判据 |
| --- | --- | --- |
| 自然适配 | T05–T06、T14、T18 | 回答结构适合当下任务，内容充分；不靠“我记得你”宣告个性化，不凭短字数得高分 |
| 被纠正后改变 | T12–T14、T18–T19 | 新范围/偏好在下一次相关任务中生效；保留必要说明，不固化为相反的另一极端 |
| 情境与状态 | T04/T08 对比 T09/T10/T17 | 能区分忙碌时段、宽裕时段与一次详解；不把时间状态当永久能力或性格 |
| 记忆适度 | T08–T24，特别 T22/T23 | 围绕当前请求，不无故重提事件、私人事实或旧路线，不频繁询问确认 |
| 协作价值 | T14、T18–T20、T24 | 建议具体、与进展相容，能帮助决定下一步；不冒充实际运行结果 |
| 解释诚实 | T16、T21、T24 | 区分明确表达与推断，来源可查才引用；对缺失信息承认覆盖不足 |

重复短语计数、字符数、提问数和记忆命中数可以作为描述统计；必须回看语境，不能从词频直接宣称“更懂用户”、讨好/共情能力或长期信任改善。

## 冻结结果报告模板

1. 运行清单：freeze ID、两文件 SHA-256、实现版本、真实 provider/model、参数、时间/费用/usage、生成与提取调用数量、错误/重试和完整性。
2. 执行有效性 V1–V5，包含 T24 实际近期历史 ID、记忆来源、是否发生污染/缺失。
3. R 项逐项对照表，给轮次、短引用、trace 路径、判定依据；T24 三个历史事实与一步行动分别列。
4. 六项体验分数和理由，注明 reviewer、是否盲评、是否实际用户评审；不可与客观结果混成一个“理解分”。
5. 差异与失败：内容命中、来源恢复、诚实缺省、无关召回和确认负担分别说明。保留两个条件所有失败，不只展示好例子。
6. 结论仅限这个脚本与这对运行。明确完整多轮产品、长期自主理解、真实用户陪伴和统计泛化仍需更多场景、重复运行与真实用户反馈。

若输出不支持冻结标准，按标准报告失败；后续修复应新建版本重跑，不能把标准改成已有答案的描述。
